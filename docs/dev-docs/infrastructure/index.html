    Infrastructure

    The shared technical foundation every platform.* module is built on top of — not a business module itself, but the plumbing all of them share.

    Why This Layer Exists

    com.softropic.skillars.infrastructure holds technical concerns that have nothing to do with any single persona or business capability — object storage, outbound email, JWT/cookie handling, rate limiting, thread-pool context propagation, the exception hierarchy, feature flags, validation annotations, and thin clients for external providers (S3, AWS SES, Google Gemini, BunnyCDN, Google Video Intelligence, an arachnid CSAM-scanning provider). None of this is "booking" or "marketplace" or "payment" logic; it is the kind of code that would otherwise get copy-pasted into every module that needed it. Factoring it out here means there is exactly one place that knows how to talk to S3, exactly one place that decides whether an email actually gets sent, and exactly one exception base class every module's domain exceptions extend.

    The architectural rule this layer enforces is: platform modules consume infrastructure through its public API, they never reach past a sibling platform module into its private wiring. The canonical example is filestorage and blobstore: every other platform module that needs to store a file (profile photos, drill videos, chat attachments) calls platform.filestorage's contract — it never imports infrastructure.blobstore.service.StorageService directly. filestorage itself is the only platform module allowed to depend on blobstore, because it adds the business rules (quota, ownership, soft-delete/retention, DB-backed metadata) that raw blob storage doesn't know about. The same shape repeats elsewhere in this layer: modules call infrastructure.email.OutboundEmailSender, infrastructure.feature.FeatureToggleService, or infrastructure.exception.ApplicationException directly (these genuinely are thin, stable, cross-cutting primitives with no business logic of their own to wrap), but anything that has business rules layered on top of a raw technical capability — like blob storage — gets its own platform-level wrapper module instead of being called directly.

    The dependency only points one way: infrastructure must not import platform.*. When an infrastructure class needs a platform value, declare a small port here and implement it in platform (e.g. RateLimitBucketTtlSource, implemented by platform.config). InfrastructureLayeringAuditTest fails on any new import com.softropic.skillars.platform… under infrastructure. It lists the four inversions that still exist (gemini ×2, RequestMetadataProvider, BunnyVideoProviderAdapter) and also fails if one of them is fixed but left on the list.

    Subpackage Reference

    blobstore

    S3 / local-filesystem object storage abstraction. Wrapped exclusively by platform.filestorage.

    security

    Cross-cutting auth primitives: cookie helpers, @RateLimited + in-memory Bucket4j rate limiting, request context, JWT/role constants, access-denied/auth-failure handlers, security events.

    feature

    Simple properties-backed feature-toggle service (features.* config keys): ARACHNID_ENABLED and VIDEOINTEL_ENABLED.

    persistence

    JPA base classes (BaseEntity, AbstractAuditingEntity), TSID generation, Flyway schema check, audit listeners, and PessimisticLockRetryer.

    email

    The OutboundEmailSender transport port + EmailTransport enum (ses/smtp/log), the SMTP and log adapters, address parsing and PII masking.

    ses

    The AWS SES implementation of the infrastructure.email transport port — active when app.email.transport=ses. The only package allowed to import the SES SDK.

    sanitizer

    Regex-based redaction of emails/phone numbers from free text (registration names, coach bio, booking notes, recaps, drill text).

    threadpool

    MDC task decorator, plus ExecutorShutdown/GracefulShutdownTaskExecutor: the per-pool drain budget on SIGTERM.

    exception

    ApplicationException — the base runtime exception (support-id, error code, log context) every module's own exceptions extend.

    video

    VideoProviderAdapter contract plus the BunnyCDN implementation: upload credentials, asset status, signed playback URLs, webhook verification, delete.

    gemini

    Thin client wrapping Google Gemini for text-content moderation, consumed by messaging and reviews.

    util

    Grab-bag of stateless helpers: Constants, JsonUtil, TimeUtil/TimeGuru, ClockProvider, RandomUtil, PhoneNumberUtil, EnvUtil, BodySanitizer, TransactionIdProvider.

    config

    App-wide @Configuration: Clock/Jackson (CommonConfig), async executor, SchedulingConfig, ShedLockConfig, the routing DataSource with its isolated pools, JPA auditing, access logs, observability.

    web

    LoggingFilter (structured request logs), Slf4jAccessLogValve (Tomcat access log via SLF4J), and FrontendLinkBuilder (absolute hash-routed SPA links).

    videointel

    Client for Google Cloud Video Intelligence, used to flag explicit content in uploaded videos before publish.

    message

    Shared REST response/error DTO shapes (Response, ErrorDto, FieldErrorDto, ErrorMsg, Success/Failure) returned by controllers app-wide.

    arachnid

    Client for a third-party CSAM (child sexual abuse material) hash-matching scanner, gating video publish before public availability.

    i18n

    WarnOnMissingMessageSource — the app's MessageSource (wired in platform.security.config.MvcConfig): an unresolvable code renders as the code plus one WARN instead of a 500.

    logging

    Small constant holders (LogKeys, InventoryCode) standardising structured-log field names across modules.

    validation

    Bean Validation annotations/validators: @Phone/@CamPhone, @Name, @LangIso2, @LocalDateWindow, @IanaTimezone, plus ISO language/phone-rule helpers.

    blobstore

    infrastructure.blobstore is the raw object-storage abstraction. The public contract is StorageService (put/get/delete/deleteAll/exists/stat/copy; deleteAll is best-effort — every key is attempted and all failures are reported together in one StorageProviderException), backed by two implementations selected via app.storage.provider: S3StorageService (default; retries transient SdkExceptions with exponential backoff via Spring Retry, sanitizes keys, uses S3TransferManager for async uploads) and LocalFileSystemStorageService (dev-mode; writes atomically via temp-file-then-move, and defends against path traversal by asserting the resolved path still starts with the configured base directory). StorageObject/StorageObjectMetadata are the return-type contracts, and StorageObjectNotFoundException/StorageProviderException are the two checked failure modes, both mapped centrally in ApiAdvice. BlobstoreProperties (app.storage.*) configures the bucket, presign/upload TTLs, retry policy, and a whole replication sub-tree for cross-region backup. The only consumer is platform.filestorage — its ReplicatedStorageService, FileStorageService, DeletionSchedulerService, and StorageMigrationService all depend on infrastructure.blobstore.service.StorageService, and its FileStorageConfig wires up the primary/backup StorageService beans by qualifier. Nothing outside filestorage imports this package.

    security

    This package is cross-cutting security plumbing consumed by every module that touches an authenticated request — it is distinct from (and depended on by) the business-facing platform.security module. SecurityConstants.java is the single source of truth for role/authority strings (ROLE_ADMIN, ROLE_COACH, ROLE_PARENT, ROLE_PLAYER, ...), @PreAuthorize SpEL expression constants (HAS_ADMIN_ROLE, HAS_COACH_ROLE, ...), cookie names (JWT_COOKIE_NAME = "potc", REFRESH_TOKEN_COOKIE = "rtkn", SKILLARS_PROFILE_COOKIE = "skp"), and token TTLs (JWT_TTL = 15 min, REFRESH_TOKEN_TTL = 7 days). CookieUtil centralizes cookie creation/removal so every cookie gets consistent Secure/SameSite/HttpOnly handling based on the current request's HTTPS status. RateLimitingService is a generic Bucket4j-backed token-bucket keyed by limitKey:identifier, used by the @RateLimited annotation/RateLimitingAspect (about two dozen endpoints) and directly by modules needing ad-hoc throttling (registration OTP resend, video upload, report generation). Buckets live in a per-instance in-memory map, so limits are per-node; an hourly @Scheduled evictIdleBuckets() removes buckets idle past security.rate_limiting.bucket_ttl_hours (runtime config, default 24h). The TTL comes through the RateLimitBucketTtlSource port, implemented in platform.config by ConfigRateLimitBucketTtlSource, so this package does not import platform. ApplicationAccessDeniedHandler, AuthenticationExceptionHandler and AjaxLogoutSuccessHandler are the Spring Security handlers wired by platform.security. Also here: RequestMetadataProvider/ClientContextProvider (current request's IP/HTTPS/locale), RequestIdProvider, and the security.event sub-package (BadCredentialsEvent, AuthEvent, PreAuthEvent) that platform.security's audit listeners subscribe to.

    feature

    A deliberately minimal feature-toggle system: AppFeature is a closed enum (ARACHNID_ENABLED, VIDEOINTEL_ENABLED) — there is no dynamic/admin-editable toggle registry, every flag must be added to this enum first. FeatureProperties binds a features.* map from application config, and PropertiesFeatureToggleService (the only FeatureToggleService implementation) fails fast at startup (@PostConstruct) if config defines a toggle key that isn't a known AppFeature, and defaults an unset toggle to a caller-supplied default (or false). Consumers call featureToggleService.isEnabled(AppFeature.X) rather than reading raw config. Today the only readers are the video moderation pipeline (ModerationOrchestrationService, gating whether CSAM/explicit-content scanning runs) and VideoModerationEmailListener, both on ARACHNID_ENABLED/VIDEOINTEL_ENABLED. (The unused PAYMENTS and INVOICING values were removed; a leftover features.toggles.payments/invoicing setting is ignored with a WARN rather than failing startup — see RETIRED_KEYS.) Don't confuse this with platform.security's FeatureGatedException, which is subscription-tier gating (e.g. radar assessments), not a toggle.

    persistence

    BaseEntity is the root @MappedSuperclass nearly every JPA entity in the codebase extends: it supplies a @Tsid-generated Long id (time-sortable, unlike UUID, and cheaper to index) plus generic equals()/hashCode() based on that id, so subclasses never need to write their own. AbstractAuditingEntity extends it and adds Spring Data JPA auditing (createdBy/createdDate/lastModifiedBy/lastModifiedDate via @CreatedBy/@CreatedDate), Hibernate Envers (@Audited), a status column (EntityStatus), plus requestId/sessionId columns populated by RequestIdAuditEntityListener and SessionIdAuditEntityListener (in infrastructure.security) so every row can be traced back to the request/session that wrote it. DbUtil.generateDbRandom() is the TSID factory entry point used wherever a sortable random id is needed outside JPA's own generator. DbSchemaChecker fails app startup if Flyway detects pending migrations (only active when custom.flyway.check-schema=true, which base application.yaml sets). Most entities extend BaseEntity or AbstractAuditingEntity; newer tables with UUID keys map their own id.

    PessimisticLockRetryer.withBoundedRetry(lockName, supplier) is the companion to every FOR UPDATE NOWAIT (findByIdForUpdate) lock in the codebase: it takes a JDBC savepoint, runs the supplier, and on PessimisticLockingFailureException rolls back to the savepoint and retries with jittered backoff (app.locking.retry.max-attempts, default 8, ≈3.2s worst case) before rethrowing, which ApiAdvice maps to 409. The supplier may run more than once, so it must only lock and read; PessimisticLockRetryerCallSiteAuditTest scans src/main/java, pins the call-site count (currently 50) and fails on any write inside a retried lambda or any NOWAIT lock without a wrapper. See Database & Migrations → Locking Conventions.

    InstanceHeartbeatMonitor is the single-instance safety net (ADR 20): every instance upserts its own row in main.app_instance_heartbeat (V187) on a fixed delay (platform.instance-heartbeat.interval-ms, default 60 s; first beat after 15 s), counts the other rows seen within three beats, and logs WARN status=MULTIPLE_INSTANCES plus the skillars.app.instances.live gauge when there is one. Plain JdbcTemplate in one TransactionTemplate (no entity; Hikari auto-commit is off), database now() for every timestamp, no @SchedulerLock (each node must beat for itself), own row deleted on graceful shutdown, rows older than a day pruned. InstanceHeartbeatMonitorIT drives it directly.

    email, ses, email.smtp, email.log — the transport port and its three implementations

    infrastructure.email.OutboundEmailSender is the one-method transport port (send(OutboundEmailRequest) -> OutboundEmailResult) that platform.notification's MailService calls — it never talks to a specific transport SDK itself. app.email.transport is bound, via EmailTransportProperties, onto the infrastructure.email.EmailTransport enum (SES/SMTP/LOG), and exactly one of three beans implements the port at a time, each gated by its own @ConditionalOnProperty(name = "app.email.transport", havingValue = ...) — the transport selection mechanism itself carries no boolean enable/disable flag; it is entirely driven by app.email.transport's three-way value. Two unrelated boolean toggles still exist elsewhere in platform.notification and are worth naming so this claim isn't read too broadly: enable.test.mail (ComponentConfig, gates the MailManager bean itself) and email.retry.enabled (EmailRetryScheduler, true in prod). Neither selects a transport — they gate different beans entirely. The three transport implementations themselves:

    • infrastructure.email.log (LoggingEmailSender) — the transport=log implementation, and what runs by default: base application.yaml sets email.transport: log explicitly (each profile then overrides it), and — for the rarer case where even that file isn't loaded, e.g. some test slices with a fully-absent property — the bean's own matchIfMissing = true covers that too. Logs every send and, when app.email.log.dump-dir is configured, writes the rendered body to disk. Note the exact sub-package — it is not collapsed into infrastructure.email itself.
    • infrastructure.ses (SesConfig, SesEmailSender, SesErrorClassifier, SesHealthIndicator, SesSendRateLimiter, SesPropertiesValidator) — active when app.email.transport=ses. SesConfig was never deleted by the transport-port migration; only its gate changed, from a boolean app.ses.enabled=true to the @ConditionalOnProperty above — it still builds the SesV2Client bean the same as before. SesPropertiesValidator is worth naming explicitly: it is the class most likely to abort a prod boot on a blank from-address or an unresolvable credential chain, and it's already cited by name in secrets-reference.md.
    • infrastructure.email.smtp (SmtpEmailSender, MailSenderProvider, SmtpPropertiesValidator, SmtpHealthIndicator) — active when app.email.transport=smtp. app.email.smtp.provider-configs is a list of ProviderConfig entries, each with six fields: name (the operator-visible label SmtpHealthIndicator surfaces per provider in the notification health group — not decorative), host, port, username, password, and implicitTls (defaults from port == 465 when unset — see skillars-deferred-99 AC5). MailSenderProvider.nextSender() round-robins across the configured providers via an AtomicInteger counter, so outbound mail is spread across whichever providers are listed (dev ships two: gmx and gmail). SmtpPropertiesValidator mirrors SesPropertiesValidator's shape — a dedicated, transport-gated @PostConstruct check — though MailSenderProvider's own constructor performs the load-bearing version of the same checks itself, since bean-creation ordering between the two is not guaranteed. MailSenderProvider honours implicitTls (skillars-deferred-111 AC10): an implicit-TLS provider uses protocol smtps with its properties under mail.smtps.*, the rest use smtp + STARTTLS; connect/read/write timeouts are 5s each, because the registration listeners call the port synchronously from an AFTER_COMMIT listener.

    Port-level pieces shared by all three adapters: OutboundEmailRequest now carries an optional headers map (validated against header injection — RFC 5322 names, no CR/LF in values), which SmtpEmailSender and SesEmailSender both apply; the notification centre uses it for List-Unsubscribe/one-click unsubscribe. Failures are classified into EmailTransportTransientException, EmailTransportPermanentException and EmailTransportRateLimitedException (by SesErrorClassifier/SmtpErrorClassifier), which drive the retry decision in platform.notification. EmailAddressParser is the one address validator (strict InternetAddress parse + validate()), and EmailPiiSanitizer masks recipient addresses in exception messages before they reach logs or envelope_entity.error. SesAccountChecker is a live, uncached SES account check behind the SES cutover preflight endpoint — it lives here because EmailTransportArchitectureTest forbids any class outside infrastructure.ses from importing the SES SDK.

    EmailTransportPropertyValidator is not what selects a bean — that would be a common but incorrect reading of its name. It is an EnvironmentPostProcessor that only validates the raw property string at startup: an absent value is legal by design (falls through to the base log default — the validator does not abort on unset, only on a present-but-unrecognised value), and matching is case-insensitive with no whitespace tolerance. Bean selection is entirely the @ConditionalOnProperty annotations named above. platform.notification is the primary consumer of the port; it is unaffected by which transport is active.

    sanitizer

    ContactDetailSanitizer is a single-purpose regex scrubber: it matches email addresses and phone-number-shaped substrings in arbitrary text and replaces them with a fixed [contact details removed] marker, returning a SanitizerResult(sanitized, wasModified) record. This exists to stop users (particularly minors messaging coaches) from exchanging off-platform contact details through free-text fields. Current callers: platform.security (player/parent/coach registration and shadow-account names, plus the SanitizePreviewResource manual-test endpoint), marketplace.CoachProfileService (bio), booking.BookingService and BookingCompletionService (booking notes, player requests, recap text — via the shared BookingService.sanitizeAndTruncate), development.SessionPrepService (plan-note suggestions) and session.DrillLibraryService (private drill text). platform.messaging does not use it — message content goes through Gemini moderation instead. SanitizerConfig is an empty @Configuration marker with no beans of its own beyond component-scanning the sanitizer.

    threadpool

    Solves one recurring problem: Spring's @Async and manually-submitted executor tasks run on a different thread than the one that submitted them, so thread-local context (the logging MDC) does not automatically follow. MdcDecorator (a TaskDecorator) captures the caller thread's MDC via ClientThreadContext, restores it on the worker thread, and — critically — merges the worker's stack trace with the caller's captured stack (via ExecutorExceptionHandler.mergeStacks) on exception, so a stack trace from a detached thread still shows where the task was originally submitted. It is wired in infrastructure.config.AsyncConfig's taskExecutor bean (distinct from platform.notification's own sendMailPool executor). Any module using @Async or submitting work to a shared pool should be aware its task runs through this decorator, not with a fresh, empty context. (AsyncConfig is registered as "skillarsAsyncConfig"; its taskExecutor uses CallerRunsPolicy on saturation.)

    Shutdown budget. ExecutorShutdown is the single place that sets wait-for-tasks/await-termination on every application pool, with a per-pool budget constant (OUTBOX_DRAIN_SECONDS 10, REPORT_SECONDS 8, SLU_RETRY_SECONDS 5, STORAGE_UPLOAD_SECONDS 5, SEND_MAIL_SECONDS 4, MODERATION_SECONDS 2, SHARED_ASYNC_SECONDS 2). Before it existed every pool took the shutdownNow() path on SIGTERM and dropped queued work. GracefulShutdownTaskExecutor escalates to shutdownNow() plus a short bounded wait once that budget is spent, because Spring's own shutdown merely logs and returns. ExecutorShutdownConfigurationTest fails if a new *Config executor bean isn't covered, and the sum of budgets feeds docker-compose.yml's stop_grace_period — a new pool needs a budget here and a compose update. Spring's own taskScheduler (which runs every @Scheduled job) is outside this class; spring.task.scheduling.shutdown.await-termination-period: 5s in application.yaml covers it.

    config — data sources, access logs, observability

    DataSourceConfig builds a single RoutingDataSource (an AbstractRoutingDataSource) over three Hikari pools that all point at the same database: the default pool (spring.datasource.hikari.*, 25 connections, auto-commit: false), gdpr-erasure-pool and payment-requires-new-pool. A caller sets RoutingDataSourceContext.set(DataSourceConfig.GDPR_ERASURE_DATASOURCE_KEY) (or PAYMENT_REQUIRES_NEW_DATASOURCE_KEY) immediately before opening a transaction and clears it in finally — today only GdprErasureService and BookingPaymentPersistenceService do. This isolates connection pools so a REQUIRES_NEW inner transaction can't starve on the pool its own suspended outer transaction is holding; it has to happen inside the one DataSource because Hibernate binds one EntityManagerFactory to one DataSource. The key is a thread-local, so it must never be set across an @Async hop.

    AccessLogConfig and ManagementAccessLogConfig register web.Slf4jAccessLogValve on the main server (9990) and the actuator server (8367) respectively, so access logs go through logback to the console JSON appender and Loki instead of a file nobody collected. The management one is registered via META-INF/spring/…ManagementContextConfiguration.imports, not component scanning — delete that entry and management access logging silently stops. ObservabilityConfig enables @Observed/@Timed AOP; CommonConfig supplies the injectable Clock (zoneId, default UTC) and the Jackson builder; JpaAuditingConfig enables JPA auditing with persistence.audit.SpringSecurityAuditorAware as the auditor. SchedulingConfig and ShedLockConfig are covered on Scheduled Jobs.

    web — logging filter, access log valve, frontend links

    LoggingFilter emits the structured request_end/request_error events. FrontendLinkBuilder (base(), route(path), resolve(pathOrUrl)) is the one way to build an absolute link into the SPA for emails and redirects. It exists because hand-built links kept getting two things wrong: the frontend origin is app.frontend-url, not the backend's own baseurl:server.port; and the Quasar router runs in hash mode, so every route lives after /#/ (a query string appended to route(...) correctly lands inside the fragment). Used by MailService, InAppNotificationService (deep links), the booking and account email listeners, StripeOnboardingResource, ReportGenerationService and the registration strategies. Don't concatenate a frontend URL by hand.

    i18n

    WarnOnMissingMessageSource is the application MessageSource (platform.security.config.MvcConfig). With setFallbackToSystemLocale(false) a code missing from every bundle used to throw NoSuchMessageException (a 500) for any locale outside de/fr/en; now it returns the code and logs one WARN. MessageBundleParityTest keeps the static bundles in parity, so this only bites dynamically-constructed codes.

    exception

    ApplicationException is the base RuntimeException that essentially all custom exceptions across every platform module extend (directly or via an intermediate per-module base like MarketplaceException or SecException). On construction it generates a short, user-shareable supportId (a Sqids-encoded hash of a random UUID — not a raw UUID, so it's compact and support-desk friendly), and its overridden getMessage() appends SUPPORT_ID: ..., ERROR_CODE: ..., MESSAGE: ... to whatever message the subclass passed in, so the support id is always present in logs even if a caller only logs ex.getMessage(). It optionally carries an ErrorCode (a marker interface most modules implement as an enum, e.g. ApplicationError.ENTITY_NOT_FOUND) and a free-form logContext map for structured logging. ResourceNotFoundException is the one concrete subclass defined here, used for generic "not found" cases outside a specific module's own not-found exception. AppSetupException and ConsumerNotFoundException round out the package. Every module's own exception hierarchy (MarketplaceException, BookingStateTransitionException, SecException and its subclasses, QuotaExceededException, etc.) extends ApplicationException so that ApiAdvice can uniformly pull supportId and logContext off any caught exception without knowing its concrete type.

    Key Flows

    Storing a file: platform module → filestorage → blobstore

    sequenceDiagram
  participant M as Platform module (e.g. video, security)
  participant FS as platform.filestorage.FileStorageService
  participant SS as infrastructure.blobstore.StorageService
  participant P as S3 / LocalFileSystem

  M->>FS: signUpload(request) / confirmUpload(key, meta)
  FS->>FS: check quota, validate content type/size
  FS->>SS: put(key, data, contentLength, contentType)
  SS->>P: upload (retries on SdkException, exponential backoff)
  P-->>SS: success / NoSuchKeyException
  SS-->>FS: void or StorageObjectNotFoundException / StorageProviderException
  FS->>FS: persist FileStorageObject row (key, owner, status)
  FS-->>M: StorageObjectDto

    No platform module other than filestorage ever imports infrastructure.blobstore.service.StorageService directly — filestorage is where quota checks, content-type/size validation, ownership, and the DB-backed FileStorageObject record live, all of which raw blob storage knows nothing about. If a new module needs to store an image or video, it should depend on platform.filestorage's contract, not add a new dependency on infrastructure.blobstore. Both StorageObjectNotFoundException and StorageProviderException bubble up through filestorage unchanged and are mapped to 404/502 centrally in platform.security.api.ApiAdvice.

    Exception → global error response

    sequenceDiagram
  participant C as Controller (any module)
  participant S as Service (any module)
  participant AE as ApplicationException subclass
  participant Advice as platform.security.api.ApiAdvice
  participant Client as HTTP client

  C->>S: business call
  S->>S: validation / state check fails
  S->>AE: throw new XyzException(msg, errorCode)
  AE->>AE: generate supportId (Sqids), attach logContext
  AE-->>Advice: propagates up as uncaught RuntimeException
  Advice->>Advice: @ExceptionHandler matches concrete exception type
  Advice->>Advice: log.error(msg, logContext, throwable) with supportId
  Advice-->>Client: ErrorDto{helpCode, errorMsg} + mapped HTTP status

    ApiAdvice has one @ExceptionHandler per concrete exception type it knows about (ResourceNotFoundException → 404, StorageProviderException → 502, QuotaExceededException → 429, BookingStateTransitionException → 409, and so on), but the logging path is generic: its private logError helper checks instanceof ApplicationException and, when true, pulls the pre-generated supportId and logContext straight off the exception rather than minting a new one. This is why every module's exceptions extend ApplicationException instead of raw RuntimeException — it's what lets one advice class produce a consistent ErrorDto/support-id pair for exceptions it has never seen a specific handler for, falling through to the generic Throwable handler as a last resort.

    Conventions & Gotchas

    Never call infrastructure.blobstore directly from another platform module. Always go through platform.filestorage. blobstore has no concept of ownership, quota, or soft-delete — those business rules live in filestorage, and bypassing it means those rules silently don't apply to whatever you stored.

    Dev writes email to disk; uat still delivers real email over SMTP. app.ses.enabled and NoOpSesEmailService no longer exist. Since ses-1.5 dev runs app.email.transport=log: nothing is sent, each rendered email (registration/OTP included) is logged and written to app.email.log.dump-dir (target/mails, one random-UUID-named .html per send — open the newest or grep for the recipient). uat still runs smtp until the SES cutover (ses-1-5b, deferred until the sending domain exists), and prod is configured for ses. A base context or test slice with no profile also falls through to log — check app.email.transport before assuming a bug in the sending code.

    All custom exceptions should extend ApplicationException, not raw RuntimeException. Doing so gets you a support id, structured log context, and automatic pickup by ApiAdvice's generic logging path for free. Bypassing it means support tickets reference a support id that was never generated.

    New feature flags must be added to the AppFeature enum before they can be configured. PropertiesFeatureToggleService fails application startup if features.* config defines a key that isn't a known enum constant — there is no free-text/dynamic toggle namespace.

    MDC is a ThreadLocal cleared with remove(), never set(null). Servlet containers and thread pools reuse threads across requests; anything that manually spawns a thread or submits to an executor outside the decorated taskExecutor bean must clear it explicitly or risk leaking one request's user context into another's logs.

    Scheduling is enabled here, and is switched off for tests. SchedulingConfig carries @EnableScheduling behind @ConditionalOnProperty("app.scheduling.enabled", matchIfMissing = true), so production and every non-test profile leave it on — only src/test/resources/application-test.yaml sets it to false. This exists because consolidating the integration suite onto a few long-lived Spring contexts removed the accidental protection short-lived contexts used to give (a job with a 5-minute delay never fires in a context that lives 90 seconds). Overriding each job's delay in test config cannot substitute: 23 of the 41 @Scheduled methods hard-code their delay or cron with no property placeholder. @EnableSchedulerLock deliberately stays on AsyncConfig and is not gated — tests invoke scheduled methods directly through the Spring proxy, so the lock advisor must still apply. See Scheduled Jobs.

    BaseEntity/AbstractAuditingEntity already implement equals()/hashCode() by id. Don't override them in subclasses unless you have a specific reason — doing so inconsistently across entities is a common source of subtle JPA collection/dedup bugs.

    A new executor pool needs a shutdown budget. Configure it through ExecutorShutdown.configureGracefulShutdown (ideally on a GracefulShutdownTaskExecutor), or ExecutorShutdownConfigurationTest fails — and re-check docker-compose.yml's stop_grace_period against the new total.

    Never hand-build a frontend URL. Use FrontendLinkBuilder.route("/coach/…"); a link without /#/ or on the backend's origin 404s or lands on the SPA root (fixed across the codebase in #307).

    Rate limits are per instance. RateLimitingService keeps Bucket4j buckets in memory, so N instances allow N× the configured rate. Fine for the single-instance deployment today (an accidental second instance is flagged by InstanceHeartbeatMonitor); revisit before scaling out.

    Consumed By

    • Security — the heaviest consumer by far; depends on cookie/rate-limiting/request-context helpers, SecurityConstants, and its own exception hierarchy extends ApplicationException.
    • Video — consumes the video (Bunny), arachnid and videointel provider adapters for upload, signed playback and content-moderation scanning, gated by the feature toggles.
    • Filestorage — the sole consumer of blobstore; also uses persistence base entities and the exception hierarchy.
    • Booking, Session, Marketplace — heavy users of PessimisticLockRetryer, persistence base entities and sanitizer for free text.
    • Payment and Admin — the two users of the isolated connection pools (RoutingDataSourceContext) for REQUIRES_NEW payment writes and GDPR erasure.
    • Messaging and Reviews — use gemini for text moderation.
    • Notification — the primary consumer of the infrastructure.email transport port, not ses specifically; ses is only the transport that's active in prod (uat runs smtp, dev runs log).
