Infrastructure

The shared technical foundation every platform.* module is built on top of — not a business module itself, but the plumbing all of them share.

Why This Layer Exists

com.softropic.skillars.infrastructure holds technical concerns that have nothing to do with any single persona or business capability — object storage, outbound email, JWT/cookie handling, rate limiting, thread-pool context propagation, the exception hierarchy, feature flags, validation annotations, and thin clients for external providers (S3, AWS SES, Google Gemini, BunnyCDN, Google Video Intelligence, an arachnid CSAM-scanning provider). None of this is "booking" or "marketplace" or "payment" logic; it is the kind of code that would otherwise get copy-pasted into every module that needed it. Factoring it out here means there is exactly one place that knows how to talk to S3, exactly one place that decides whether an email actually gets sent, and exactly one exception base class every module's domain exceptions extend.

The architectural rule this layer enforces is: platform modules consume infrastructure through its public API, they never reach past a sibling platform module into its private wiring. The canonical example is filestorage and blobstore: every other platform module that needs to store a file (profile photos, drill videos, chat attachments) calls platform.filestorage's contract — it never imports infrastructure.blobstore.service.StorageService directly. filestorage itself is the only platform module allowed to depend on blobstore, because it adds the business rules (quota, ownership, soft-delete/retention, DB-backed metadata) that raw blob storage doesn't know about. The same shape repeats elsewhere in this layer: modules call infrastructure.ses.SesEmailService, infrastructure.feature.FeatureToggleService, or infrastructure.exception.ApplicationException directly (these genuinely are thin, stable, cross-cutting primitives with no business logic of their own to wrap), but anything that has business rules layered on top of a raw technical capability — like blob storage — gets its own platform-level wrapper module instead of being called directly.

Subpackage Reference

blobstore

S3 / local-filesystem object storage abstraction. Wrapped exclusively by platform.filestorage.

security

Cross-cutting auth primitives: cookie helpers, rate limiting, request context, JWT/role constants, security error events.

feature

Simple properties-backed feature-toggle service (features.* config keys) gating payments, invoicing, arachnid, videointel.

persistence

JPA base classes (BaseEntity, AbstractAuditingEntity), TSID generation, Flyway schema check, audit listeners.

ses

AWS SES email sending, with a NoOpSesEmailService that silently swallows sends when disabled.

sanitizer

Regex-based redaction of emails/phone numbers from free text, used to strip contact info from user-generated content.

threadpool

MDC task decorator and executor wiring so @Async/detached threads keep the originating request's logging context.

exception

ApplicationException — the base runtime exception (support-id, error code, log context) every module's own exceptions extend.

video

VideoProviderAdapter contract plus the BunnyCDN implementation used for upload/playback/webhook handling.

gemini

Thin client wrapping Google Gemini for text-content moderation, consumed by messaging's moderation service.

util

Grab-bag of stateless helpers: Constants, JsonUtil, TimeUtil/TimeGuru, ClockProvider, RandomUtil, PhoneNumberUtil, EnvUtil.

config

App-wide Spring @Configuration classes: Jackson/ObjectMapper setup, async executor, SchedulingConfig, datasource, JPA auditing, ShedLock, observability.

web

LoggingFilter — the one shared servlet filter, emitting structured request_end/request_error log events.

videointel

Client for Google Cloud Video Intelligence, used to flag explicit content in uploaded videos before publish.

message

Shared REST response/error DTO shapes (Response, ErrorDto, ErrorMsg, Success/Failure) returned by controllers app-wide.

arachnid

Client for a third-party CSAM (child sexual abuse material) hash-matching scanner, gating video publish before public availability.

client

AbstractClient — shared RestTemplate wiring (timeouts, interceptors, JSON converters) that provider-specific clients extend.

logging

Small constant holders (LogKeys, InventoryCode) standardising structured-log field names across modules.

validation

Bean Validation annotations/validators: @Phone, @Name, @LangIso2, @LocalDateWindow, @IanaTimezone, plus ISO language/phone helpers.

blobstore

infrastructure.blobstore is the raw object-storage abstraction. The public contract is StorageService (put/get/delete/exists/stat/copy), backed by two implementations selected via app.storage.provider: S3StorageService (default; retries transient SdkExceptions with exponential backoff via Spring Retry, sanitizes keys, uses S3TransferManager for async uploads) and LocalFileSystemStorageService (dev-mode; writes atomically via temp-file-then-move, and defends against path traversal by asserting the resolved path still starts with the configured base directory). StorageObject/StorageObjectMetadata are the return-type contracts, and StorageObjectNotFoundException/StorageProviderException are the two checked failure modes, both mapped centrally in ApiAdvice. BlobstoreProperties (app.storage.*) configures the bucket, presign/upload TTLs, retry policy, and a whole replication sub-tree for cross-region backup. The only consumer is platform.filestorage — its ReplicatedStorageService, FileStorageService, DeletionSchedulerService, and StorageMigrationService all depend on infrastructure.blobstore.service.StorageService, and its FileStorageConfig wires up the primary/backup StorageService beans by qualifier. Nothing outside filestorage imports this package.

security

This package is cross-cutting security plumbing consumed by every module that touches an authenticated request — it is distinct from (and depended on by) the business-facing platform.security module. SecurityConstants.java is the single source of truth for role/authority strings (ROLE_ADMIN, ROLE_COACH, ROLE_PARENT, ROLE_PLAYER, ...), @PreAuthorize SpEL expression constants (HAS_ADMIN_ROLE, HAS_COACH_ROLE, ...), cookie names (JWT_COOKIE_NAME = "potc", REFRESH_TOKEN_COOKIE = "rtkn", SKILLARS_PROFILE_COOKIE = "skp"), and token TTLs (JWT_TTL = 15 min, REFRESH_TOKEN_TTL = 7 days). CookieUtil centralizes cookie creation/removal so every cookie gets consistent Secure/SameSite/HttpOnly handling based on the current request's HTTPS status. RateLimitingService is a generic Bucket4j-backed token-bucket keyed by limitKey:identifier, used by the @RateLimited annotation/aspect and directly by modules needing ad-hoc throttling (login attempts, OTP resend). Also here: RequestMetadataProvider/ClientContextProvider (current request's IP/HTTPS/locale), RequestIdProvider, and the security.event sub-package (BadCredentialsEvent, FraudEvent, PreAuthEvent) that platform.security's audit listeners subscribe to.

feature

A deliberately minimal feature-toggle system: AppFeature is a closed enum (PAYMENTS, INVOICING, ARACHNID_ENABLED, VIDEOINTEL_ENABLED) — there is no dynamic/admin-editable toggle registry, every flag must be added to this enum first. FeatureProperties binds a features.* map from application config, and PropertiesFeatureToggleService (the only FeatureToggleService implementation) fails fast at startup (@PostConstruct) if config defines a toggle key that isn't a known AppFeature, and defaults an unset toggle to a caller-supplied default (or false). Consumers call featureToggleService.isEnabled(AppFeature.PAYMENTS) rather than reading raw config — platform.security's FeatureGatedException path and the video moderation pipeline (ARACHNID_ENABLED/VIDEOINTEL_ENABLED, gating whether CSAM/explicit-content scanning actually runs) are the main consumers.

persistence

BaseEntity is the root @MappedSuperclass nearly every JPA entity in the codebase extends: it supplies a @Tsid-generated Long id (time-sortable, unlike UUID, and cheaper to index) plus generic equals()/hashCode() based on that id, so subclasses never need to write their own. AbstractAuditingEntity extends it and adds Spring Data JPA auditing (createdBy/createdDate/lastModifiedBy/lastModifiedDate via @CreatedBy/@CreatedDate), Hibernate Envers (@Audited), a status column (EntityStatus), plus requestId/sessionId columns populated by RequestIdAuditEntityListener and SessionIdAuditEntityListener (in infrastructure.security) so every row can be traced back to the request/session that wrote it. DbUtil.generateDbRandom() is the TSID factory entry point used wherever a sortable random id is needed outside JPA's own generator. DbSchemaChecker fails app startup if Flyway detects pending migrations (only active when custom.flyway.check-schema=true). Every entity in every platform module ultimately extends BaseEntity or AbstractAuditingEntity.

ses

SesEmailService is a one-method contract (send(to, subject, htmlBody)) with two mutually-exclusive Spring-conditional implementations. SesEmailServiceImpl activates only when app.ses.enabled=true, calling AWS SESv2 and wrapping SDK failures in SesException. NoOpSesEmailService activates whenever app.ses.enabled=false or the property is simply absent (matchIfMissing = true) — it just logs "NoOp SES: email suppressed" and returns. This is the default in local/dev environments: no AWS credentials are needed and no real email goes out, but callers get no error either, which is a common source of "why didn't my email arrive" confusion during local testing. SesConfig only creates the SesV2Client bean when SES is enabled. platform.notification is the primary consumer, sending through this interface rather than touching the AWS SDK directly.

sanitizer

ContactDetailSanitizer is a single-purpose regex scrubber: it matches email addresses and phone-number-shaped substrings in arbitrary text and replaces them with a fixed [contact details removed] marker, returning a SanitizerResult(sanitized, wasModified) record. This exists to stop users (particularly minors messaging coaches) from exchanging off-platform contact details inside in-app messages, and to strip contact info from free-text fields at registration. It is used by platform.messaging (message content) and platform.security (registration name/bio fields, and exposed for manual testing via /api/util/sanitize-preview). SanitizerConfig is an empty @Configuration marker with no beans of its own beyond component-scanning the sanitizer.

threadpool

Solves one recurring problem: Spring's @Async and manually-submitted executor tasks run on a different thread than the one that submitted them, so thread-local context (the logging MDC) does not automatically follow. MdcDecorator (a TaskDecorator) captures the caller thread's MDC via ClientThreadContext, restores it on the worker thread, and — critically — merges the worker's stack trace with the caller's captured stack (via ExecutorExceptionHandler.mergeStacks) on exception, so a stack trace from a detached thread still shows where the task was originally submitted. It is wired in infrastructure.config.AsyncConfig's taskExecutor bean (distinct from platform.notification's own sendMailPool executor). Any module using @Async or submitting work to a shared pool should be aware its task runs through this decorator, not with a fresh, empty context. A second TenantContextTaskDecorator used to be composed in here; it was deleted with the tenant module, and AsyncConfig's bean name changed from "tenantAsyncConfig" to "skillarsAsyncConfig" at the same time.

exception

ApplicationException is the base RuntimeException that essentially all custom exceptions across every platform module extend (directly or via an intermediate per-module base like MarketplaceException or SecException). On construction it generates a short, user-shareable supportId (a Sqids-encoded hash of a random UUID — not a raw UUID, so it's compact and support-desk friendly), and its overridden getMessage() appends SUPPORT_ID: ..., ERROR_CODE: ..., MESSAGE: ... to whatever message the subclass passed in, so the support id is always present in logs even if a caller only logs ex.getMessage(). It optionally carries an ErrorCode (a marker interface most modules implement as an enum, e.g. ApplicationError.ENTITY_NOT_FOUND) and a free-form logContext map for structured logging. ResourceNotFoundException is the one concrete subclass defined here, used for generic "not found" cases outside a specific module's own not-found exception. AppSetupException and ConsumerNotFoundException round out the package. Every module's own exception hierarchy (MarketplaceException, BookingStateTransitionException, SecException and its subclasses, QuotaExceededException, etc.) extends ApplicationException so that ApiAdvice can uniformly pull supportId and logContext off any caught exception without knowing its concrete type.

Key Flows

Storing a file: platform module → filestorage → blobstore

sequenceDiagram
  participant M as Platform module (e.g. video, security)
  participant FS as platform.filestorage.FileStorageService
  participant SS as infrastructure.blobstore.StorageService
  participant P as S3 / LocalFileSystem

  M->>FS: signUpload(request) / confirmUpload(key, meta)
  FS->>FS: check quota, validate content type/size
  FS->>SS: put(key, data, contentLength, contentType)
  SS->>P: upload (retries on SdkException, exponential backoff)
  P-->>SS: success / NoSuchKeyException
  SS-->>FS: void or StorageObjectNotFoundException / StorageProviderException
  FS->>FS: persist FileStorageObject row (key, owner, status)
  FS-->>M: StorageObjectDto

No platform module other than filestorage ever imports infrastructure.blobstore.service.StorageService directly — filestorage is where quota checks, content-type/size validation, ownership, and the DB-backed FileStorageObject record live, all of which raw blob storage knows nothing about. If a new module needs to store an image or video, it should depend on platform.filestorage's contract, not add a new dependency on infrastructure.blobstore. Both StorageObjectNotFoundException and StorageProviderException bubble up through filestorage unchanged and are mapped to 404/502 centrally in platform.security.api.ApiAdvice.

Exception → global error response

sequenceDiagram
  participant C as Controller (any module)
  participant S as Service (any module)
  participant AE as ApplicationException subclass
  participant Advice as platform.security.api.ApiAdvice
  participant Client as HTTP client

  C->>S: business call
  S->>S: validation / state check fails
  S->>AE: throw new XyzException(msg, errorCode)
  AE->>AE: generate supportId (Sqids), attach logContext
  AE-->>Advice: propagates up as uncaught RuntimeException
  Advice->>Advice: @ExceptionHandler matches concrete exception type
  Advice->>Advice: log.error(msg, logContext, throwable) with supportId
  Advice-->>Client: ErrorDto{helpCode, errorMsg} + mapped HTTP status

ApiAdvice has one @ExceptionHandler per concrete exception type it knows about (ResourceNotFoundException → 404, StorageProviderException → 502, QuotaExceededException → 429, BookingStateTransitionException → 409, and so on), but the logging path is generic: its private logError helper checks instanceof ApplicationException and, when true, pulls the pre-generated supportId and logContext straight off the exception rather than minting a new one. This is why every module's exceptions extend ApplicationException instead of raw RuntimeException — it's what lets one advice class produce a consistent ErrorDto/support-id pair for exceptions it has never seen a specific handler for, falling through to the generic Throwable handler as a last resort.

Conventions & Gotchas

Never call infrastructure.blobstore directly from another platform module. Always go through platform.filestorage. blobstore has no concept of ownership, quota, or soft-delete — those business rules live in filestorage, and bypassing it means those rules silently don't apply to whatever you stored.

Emails are silently suppressed in most local/dev setups. NoOpSesEmailService activates whenever app.ses.enabled is false or unset — there is no error, no exception, just a log line ("NoOp SES: email suppressed"). If a verification email or notification "isn't arriving" during local development, check for that log line before assuming a bug in the sending code.

All custom exceptions should extend ApplicationException, not raw RuntimeException. Doing so gets you a support id, structured log context, and automatic pickup by ApiAdvice's generic logging path for free. Bypassing it means support tickets reference a support id that was never generated.

New feature flags must be added to the AppFeature enum before they can be configured. PropertiesFeatureToggleService fails application startup if features.* config defines a key that isn't a known enum constant — there is no free-text/dynamic toggle namespace.

MDC is a ThreadLocal cleared with remove(), never set(null). Servlet containers and thread pools reuse threads across requests; anything that manually spawns a thread or submits to an executor outside the decorated taskExecutor bean must clear it explicitly or risk leaking one request's user context into another's logs.

Scheduling is enabled here, and is switched off for tests. SchedulingConfig carries @EnableScheduling behind @ConditionalOnProperty("app.scheduling.enabled", matchIfMissing = true), so production and every non-test profile leave it on — only src/test/resources/application-test.yaml sets it to false. This exists because consolidating the integration suite onto a few long-lived Spring contexts removed the accidental protection short-lived contexts used to give (a job with a 5-minute delay never fires in a context that lives 90 seconds). Overriding each job's delay in test config cannot substitute: 16 of the 30 @Scheduled methods hard-code their delay or cron with no property placeholder. @EnableSchedulerLock deliberately stays on AsyncConfig and is not gated — tests invoke scheduled methods directly through the Spring proxy, so the lock advisor must still apply. See Scheduled Jobs.

BaseEntity/AbstractAuditingEntity already implement equals()/hashCode() by id. Don't override them in subclasses unless you have a specific reason — doing so inconsistently across entities is a common source of subtle JPA collection/dedup bugs.

Consumed By

  • Security — the heaviest consumer by far; depends on cookie/rate-limiting/request-context helpers, SecurityConstants, and its own exception hierarchy extends ApplicationException.
  • Video — consumes the video, arachnid, videointel, and gemini provider adapters for upload/playback and content-moderation scanning.
  • Filestorage — the sole consumer of blobstore; also uses persistence base entities and the exception hierarchy.
  • Booking and Session — heavy users of persistence base entities, threadpool-decorated async work, and ApplicationException subclassing.
  • Payment — uses client.AbstractClient for outbound provider HTTP calls and the feature toggle service (PAYMENTS/INVOICING).
  • Messaging — uses sanitizer for contact-detail redaction and gemini for moderation.
  • Notification — the primary consumer of ses for outbound email.
  • Admin — consumes security/persistence primitives for cross-cutting admin operations.
