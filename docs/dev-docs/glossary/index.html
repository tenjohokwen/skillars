    Glossary

    Domain and codebase jargon, A–Z. Each entry gives a short definition, the page that covers it in depth, and the main class or table to grep for. Link to an entry with glossary/index.html#<term-slug>.

    A · B · C · D · E · F · G · H · I · L · M · N · O · P · R · S · T · V · W

    New here? The Your First Day page walks the core loop in which most of these terms appear, in order.

    A

    Admin alert / moderation queue

    The admin back office's single work queue. Events from other modules (reported messages, AI-moderation holds, flagged reviews, strike thresholds, disputes, GDPR deadline overruns, orphaned subscriptions) become one de-duplicated OPEN alert row each, served at /admin/moderation.

    See Admin · Code AdminAlertEventListener, AdminQueueService, table admin.admin_alerts

    Age tier

    A player's age bracket, derived from date of birth: U10 (age ≤ 9), AGE_10_12 (≤ 12), AGE_13_17 (≤ 17) and ADULT. The boundaries are inclusive maxima read from platform_config keys security.age-policy.u10-max-age (9), security.age-policy.young-teen-max-age (12) and security.age-policy.teen-max-age (17), seeded in V139, with the same values hard-coded in AgePolicy.defaults() as fallback. The tier drives the messaging policy, whether self-registration is allowed (18+ only) and the minor-safety gate. Not to be confused with player subscription tiers.

    See Security · Code AgePolicyService.getAgeTier, enum AgeTier, column main.player_profiles.age_tier

    Appeal

    A user's one-time challenge to an enforcement action: a reliability strike, a coach suspension, a blocked review, or a dispute resolution. It must be filed within 14 days. An admin decides it UPHELD or OVERTURNED, the decision is final, and an overturn applies the reversal in the same transaction.

    See Admin · Code AppealService, AppealSubjectType, /api/appeals, table admin.appeals (V172)

    Availability window / block

    A window is a recurring weekly slot a coach is bookable in (e.g. Tuesdays 16:00–19:00), interpreted in the coach's canonical timezone. A block is a one-off blackout period. Every booking, reschedule and duplicate must fall inside a window and outside every block.

    See Booking · Code AvailabilityService, CoachAvailabilityWindow (marketplace table), CoachAvailabilityBlock (booking.coach_availability_blocks)

    Availability signature

    A hash of the coach's windows that the client sends back with a create, batch-create or reschedule request. If the coach changed their availability since the calendar was loaded, the request fails with booking.availabilityChanged instead of booking against a stale view.

    See Booking · Code AvailabilityService.computeAvailabilitySignature

    B

    Batch booking

    Several slots with one coach requested in a single submission (up to booking.batch.maxSize, seeded 5, bounded 1–100). The coach can accept the whole batch at once. The batch status rolls up from its members (PENDING, PARTIALLY_ACCEPTED, FULLY_ACCEPTED, DECLINED), and payment settles each member in its own transaction.

    See Booking · Code BookingBatchService, BookingBatch, table booking.booking_batches

    Booker

    The paying account on a booking: a parent booking for their child, or a self-registered adult player booking for themselves. Either way its user id is stored in Booking.parentId, so "parent" in booking and payment code usually means "booker". Booker endpoints are guarded by HAS_PARENT_OR_PLAYER_ROLE.

    See Booking · Code Booking.parentId, SecurityConstants.HAS_PARENT_OR_PLAYER_ROLE

    Booking status

    The booking lifecycle, enforced by a state machine. The happy path is REQUESTED → ACCEPTED/PAYMENT_PENDING → CONFIRMED → UPCOMING (reminder window) → IN_PROGRESS/PAUSED → COMPLETED, with COMPLETED_PENDING_CONFIRMATION for a QUICK wrap-up and terminal side states for declines, cancellations, no-shows and disputes. All status changes go through BookingService.transition().

    See Booking · Code enum BookingStatus, BookingStateMachine, CHECK chk_bkg_status

    Bunny

    Bunny.net Stream, the third-party video host. Clients upload directly to Bunny over TUS, Bunny transcodes and stores the media, and its webhooks report upload and encoding results. Video is stored there, not in S3 through filestorage.

    See Video, Infrastructure · Code infrastructure.video.BunnyVideoProviderAdapter, VideoProviderAdapter, webhook inbox main.video_webhook_events

    C

    Canonical timezone

    The coach profile's IANA zone. Availability windows and the "no booking across local midnight" rule are evaluated in it, and each booking copies it at creation (UTC fallback) so later profile edits don't shift existing bookings.

    See Booking · Code CoachProfile.canonicalTimezone, Booking.canonicalTimezone

    Coach access window

    How long after the last attended session a coach may still read and write a player's development data (and play their videos). Development uses development.timeline.coachAccessExpiryDays (90); video uses platform.video.access.coach_window_days (90).

    See Development, Video · Code CoachAccessWindow, CoachPlayerAuthorizationService, VideoAccessGuard

    Coach status

    The marketplace state of a coach profile: DRAFT (profile builder not published), ACTIVE (listed and bookable), REDUCED (bookable but with reduced search visibility after reaching the strike visibility threshold), PENDING_REVIEW (strike suspension threshold reached, waiting for an admin), SUSPENDED (admin action, cannot accept bookings) and DEACTIVATED. New requests are allowed for ACTIVE, REDUCED and PENDING_REVIEW. There is no automatic suspension.

    See Marketplace, Admin · Code enum CoachProfileStatus, column marketplace.coach_profiles.status

    Coach subscription tier

    The coach's paid plan: SCOUT (the default at publish: drill library and session builder), INSTRUCTOR (adds Skills Radar, performance reports, drill video upload, more storage) and ACADEMY (adds report branding and the SLU/Radar correlation engine). Feature gates read the marketplace projection; payment holds the billing truth and syncs the tier across. A missing marketplace row reads as SCOUT.

    See Payment, Marketplace · Code enum CoachSubscriptionTier, CoachProfileService.getCoachSubscriptionTier, tables marketplace.coach_subscriptions / payment.coach_subscriptions

    Command Center

    The coach's day-of-session page (/coach/command-center): schedule, start/pause/resume/end of a live session, the wrap-up sequence and recap prompts.

    See Frontend, Booking · Code CoachCommandCenterPage.vue, WrapUpSequence.vue, BookingCompletionService

    Contact-detail sanitizer

    The filter that strips phone numbers, emails and similar off-platform contact details from free text (booking notes, recaps, registration names) before it is stored, so users cannot route around the platform or reach minors directly.

    See Infrastructure · Code infrastructure.sanitizer.ContactDetailSanitizer

    Credit wallet

    A booker's euro balance on the platform. Refunds never go back to a card: they land here as credit, which is spent first on later bookings. A parent can cash credit out to their card minus a Stripe fee. The balance is the sum of an append-only ledger (UPDATE/DELETE are rejected by triggers) whose entry types are BOOKING_DEDUCTION, BOOKING_DEDUCTION_REVERSAL, BOOKING_REFUND, CASH_OUT_DEBIT, STRIPE_FEE_DEBIT and CASH_OUT_REVERSAL.

    See Payment · Code CreditWalletService, ParentCreditLedger, table payment.parent_credit_ledger, view payment.parent_credit_balance

    D

    Dispute

    A complaint about a terminal booking, raised by the booker or the coach within disputes.submissionWindowDays (14). An admin resolves it with FULL_CREDIT, PARTIAL_CREDIT, NO_ACTION or COACH_WARNING, or dismisses it. A resolution that credits the booker also reaches the coach in the same transaction: a payout still inside the hold is set to CANCELLED, and an already released one gets a proportional transfer reversal through the outbox. A dispute also locks the booking's recap.

    See Admin, Payment · Code DisputeService, /api/disputes, table admin.disputes

    Drill (PLATFORM vs PRIVATE)

    A training exercise with JSONB metadata (skills, weighting, intensity, equipment, coaching points). PLATFORM drills are curated and owner-less (20 are seeded); PRIVATE drills belong to one coach, either authored from scratch or cloned from a platform drill. A coach may use every platform drill and their own private ones, never another coach's. Older comments say COACH; the DB value is PRIVATE.

    See Session · Code Drill, DrillUsagePolicy, table session.drills (CHECK chk_drill_owner)

    E

    Envelope (email)

    The in-memory model of one outbound email: recipients, an EmailTemplate, a delivery deadline, template data and an idempotent sendId. It is persisted for retry and per-recipient delivery tracking, so a resend cannot double-deliver.

    See Notification · Code record notification.contract.Envelope, EnvelopeEntity, table main.envelope_entity, EmailRetryScheduler

    F

    Feature gate

    A check that a coach's or player's subscription tier allows a feature, read from per-tier platform_config booleans (e.g. coach.tier.scout.video_upload) or the tier itself. A denied call throws FeatureGatedException and the frontend shows a teaser. Separate global switches for external integrations live in AppFeature (e.g. ARACHNID_ENABLED).

    See Config, Development · Code FeatureGatedException, infrastructure.feature.AppFeature

    Force-complete

    Completing a booking that got stuck at wrap-up by writing placeholder completion data, so payout and downstream processing can proceed. It is done automatically by a sweeper after booking.stuck_completion_timeout_hours or by an admin from /admin/bookings. Both share one code path.

    See Booking, Admin · Code BookingCompletionService.forceCompleteWithPlaceholderData, StuckCompletionSweeperService, AdminBookingCompletionService

    FrontendLinkBuilder / hash routing

    The SPA uses Vue Router hash mode (vueRouterMode: 'hash'), so every in-app URL looks like <frontendUrl>/#/coach/.... Links the backend puts in emails and notifications must be built with FrontendLinkBuilder (base(), route(path), resolve(pathOrUrl)), never by string concatenation. The base URL comes from app.frontend-url.

    See Infrastructure, Frontend · Code infrastructure.web.FrontendLinkBuilder, src/frontend/quasar.config.js

    G

    GDPR export / erasure (self vs child scope)

    Data-subject requests. Any user can request an export (a ZIP behind a signed, time-limited URL) or an erasure of their own data (/api/gdpr/export, /api/gdpr/erasure). A parent can do the same for a child's shadow profile (/api/gdpr/players/{playerId}/export|erasure). Such a request carries the parent's user_id plus a non-null player_id, and must never be routed to the self-erasure path, which would anonymise the parent. Erasure runs on its own connection pool, cascades through every module, leaves tombstones, and failed runs are retried daily.

    See Admin · Code GdprRequestService, GdprExportService, GdprErasureService.erase / eraseChild, GdprErasureRetryScheduler, table admin.gdpr_requests

    H

    Homework (Locker Room)

    Up to two drills the coach picks at wrap-up for the player to practise before the next session. It is materialised in the session module once the booking completes; there is no separate "create homework" endpoint. Players and parents see and tick it off in the Locker Room (/player/locker-room/:playerId).

    See Session · Code HomeworkAssignmentService, HomeworkAssignment, table session.homework_assignments

    I

    ID spaces

    Several id types look alike but are not interchangeable. User ids and PlayerProfile ids are both Long, and Booking.playerId is a PlayerProfile PK, not a user id: resolve the human via PlayerProfile.userId / parentId. Coach ids in booking, payment and session are CoachProfile UUIDs, not the coach's user id.

    See Home (Conventions), Booking · Code Booking, PlayerProfile, CoachProfile

    L

    LIVE vs QUICK completion

    The two ways to finish a session, carried in WrapUpRequest.mode. LIVE: the coach ran the session in the Command Center (start/end) and the wrap-up completes the booking immediately. QUICK: the coach marks it done afterwards. The booking waits in COMPLETED_PENDING_CONFIRMATION for the booker to confirm and is auto-confirmed after booking.quick_complete_timeout_hours (24). A QUICK wrap-up freezes the session plan's blocks into plan_blocks_snapshot, so SLU and the timeline compute from what was planned at that moment.

    See Booking · Code BookingCompletionService.submitWrapUp, SessionCompletionData.completionMode, QuickCompleteTimeoutService, QuickPlanSnapshot

    Log transport (target/mails)

    The dev profile's email transport (app.email.transport: log). Nothing is sent; each rendered email is logged and written to target/mails/<correlationId>.html, which is where you find verification links and OTP codes locally. UAT uses smtp, production ses.

    See Notification, Your First Day · Code infrastructure.email.log.LoggingEmailSender, application-dev.yaml

    M

    Messaging policy

    What a player may do in messaging, derived from their age tier: U10 prohibited, AGE_10_12 parent-managed, AGE_13_17 supervised, ADULT unrestricted. Security computes it and messaging consumes it; never re-derive age rules locally.

    See Messaging, Security · Code MessagingPolicy, AgePolicyService.getMessagingPolicy

    Minor-safety gate / minors never upload

    Minors never upload (ADR 18). A player upload whose profile is a minor, parent-managed or has no date of birth is refused at initiation (403 VIDEO_MINOR_UPLOAD_REFUSED) and alerts an admin. The third layer of video moderation re-checks the same rule and fails closed: such a video is hidden and never transcoded. The old parental-approval flow (/parent/approvals) was removed.

    See Video · Code MinorUploadPolicy, ModerationOrchestrationService

    Video subject (coach video of a child)

    The session and child a coach video is about (videos.subject_booking_id / subject_player_id, V184). A COACH_REVIEW must name one of the coach's held sessions; the child's parent, and the child themself if self-registered, may play it (never download or delete). GDPR erasure of the child purges it.

    See Video · Code VideoSubjectService, VideoAccessGuard.isSubjectViewer

    N

    Neglected skill

    A skill whose actual weekly SLU fell more than slu.neglected.threshold below the highest weekly target any of the player's coaches set for it. A ShedLock-guarded job runs Mondays 06:00 UTC, opens a flag, and auto-resolves it when training recovers. It measures training volume only, not ability.

    See Development · Code NeglectedSkillDetectionService, NeglectedSkillProcessor, NeglectedSkillFlag (development.neglected_skill_flags), PlayerSluTarget

    NOWAIT + PessimisticLockRetryer

    The row-locking convention for hot rows (coach profile, booking, wallet, drill, review…). findByIdForUpdate issues SELECT … FOR UPDATE NOWAIT, which fails immediately on contention instead of blocking, and the call is wrapped in PessimisticLockRetryer.withBoundedRetry, which retries behind a savepoint with jittered backoff and maps exhaustion to a 409. The retried lambda must only read; PessimisticLockRetryerCallSiteAuditTest pins the call-site count and rejects writes inside it. Inside a REQUIRES_NEW transaction, NOWAIT-locking a row the suspended caller already wrote always fails (Postgres 55P03).

    See Database, Infrastructure · Code infrastructure.persistence.PessimisticLockRetryer

    Notification category / opt-out

    Every email template is classified into one NotificationCategory (BOOKING, REMINDER, SESSION_PACK, DEVELOPMENT, MODERATION, ACCOUNT, SYSTEM). Only REMINDER and DEVELOPMENT can be opted out of; the rest are transactional. Opt-out is checked at send time, carries a one-click unsubscribe link plus List-Unsubscribe headers, and never suppresses the in-app inbox row.

    See Notification · Code NotificationCategory, NotificationCatalog, NotificationPreferenceService, tables main.notification_email_preferences, main.user_notifications

    O

    Outbox

    The generic transactional outbox. A producer inserts an intent row (refund, payout transfer, email, blob deletion…) in the same transaction as its business change; after commit, and again every five minutes, a drainer claims due rows with SKIP LOCKED and runs the matching handler, retrying with backoff forever. Handlers must be idempotent. Several module-private queues are also called "outbox"; they are separate tables.

    See Outbox · Code OutboxService, OutboxMessageHandler, table main.outbox_messages

    P

    Payout hold

    The delay between session completion and paying the coach. Completion writes a PENDING_RELEASE payout row with release_after = now + payment.payout.hold_hours (48, bounded 0–336) and an outbox transfer message not due before then, so a dispute can stop the payout before money reaches the coach. A non-retryable Stripe error moves the row to HOLD, which needs manual follow-up. A booking paid entirely by credit or a pack has no card charge to share, so no transfer happens.

    See Payment, Outbox · Code CoachPayoutEnqueueListener, CoachPayoutOutboxSupport, CoachPayoutTransferHandler, table payment.coach_payouts

    platform_config

    The database-backed key/value store for business knobs: per-tier feature gates, quotas, thresholds, timers and age-tier cutoffs. Values are typed strings, cached per node, editable at /admin/config within ranges defined in ConfigBounds, and validated at boot by ConfigStartupAssertion. Seeds live in V139__baseline_seed_data.sql and later migrations. (Not to be confused with admin.config.PlatformConfig, an unrelated @Configuration class.)

    See Config · Code ConfigService, config.repo.PlatformConfig, table main.platform_config

    Player subscription tier

    A player's paid plan: ATHLETE, SEMI_PRO or PRO, which unlock video and Skills Radar features. SEMI_PRO and PRO are billed yearly only (CHECK constraints). Video retention is the main consumer: when a subscription lapses the player's videos are blocked, then archived and purged, except that a YEARLY subscription pauses the archival clock. Not required for booking.

    See Payment, Video · Code PlayerSubscriptionTierBilling, PlayerSubscriptionQueryAdapter, table payment.player_subscriptions

    Profile builder / publish

    The coach's five-step onboarding wizard (/coach/profile-builder): identity, specialties, age groups, pricing, availability. Publishing validates all steps, flips the profile from DRAFT to ACTIVE (visible in search) and creates the SCOUT subscription row. Nothing is bookable until it has been published.

    See Marketplace · Code ProfileBuilderResource, CoachProfileService.publishProfile

    R

    Recap

    The coach's short post-session summary in three fields: "what we did", "what's next" and "what went well". It is written at wrap-up and editable until booking.recap.editWindowDays (30) after the session, unless the coach or player was GDPR-erased or a dispute locks it. Recaps appear on the player's timeline and Session Prep Card and in reports.

    See Booking, Development · Code BookingCompletionService.updateRecap, SessionCompletionData (booking.session_completion_data)

    Reliability strike

    A mark against a coach for a no-show, or for a coach cancellation whose reason is not exempt (MUTUAL_AGREEMENT, HEALTH_MEDICAL, FAMILY_EMERGENCY and WEATHER are). Strikes are counted over the trailing 30 days: reaching reliability.strike.visibilityThreshold (3) sets the coach to REDUCED, and reaching reliability.strike.suspensionThreshold (5) sets PENDING_REVIEW and raises an admin alert. Admins can also issue and delete strikes, and coaches can appeal them.

    See Payment, Admin · Code ReliabilityStrikeService, ReliabilityStrikeConfig, CoachReliabilityStrike (marketplace.coach_reliability_strikes)

    Routing DataSource

    One AbstractRoutingDataSource over three Hikari pools on the same database: the default pool, gdpr-erasure-pool and payment-requires-new-pool. A caller sets a thread-local key right before opening a REQUIRES_NEW transaction (and clears it in finally), so the inner transaction can't starve on the pool its own suspended outer transaction holds. Today only GDPR erasure and payment persistence use it.

    See Infrastructure · Code DataSourceConfig, RoutingDataSourceContext

    S

    Self-registered player

    An adult (18+) who signs up as a player with their own login and books for themselves, acting as their own booker. Their PlayerProfile has user_id set and parent_id null. Registration under 18 is rejected outright, because minors must be created by a parent as shadow profiles.

    See Security · Code PlayerRegistrationService, ShadowAccountService.createSelfOwnedPlayerProfile, CHECK chk_pp_owner

    Session DNA

    A computed 0–100 profile of a session plan or template across technical, physical, cognitive, match-realism and weak-foot focus, derived from the drills' metadata together with an equipment checklist.

    See Session · Code SessionDnaCalculator, column session.sessions.session_dna

    Session pack

    A coach-defined bundle of prepaid sessions at a fixed per-session price. Bookings funded by a pack decrement its remaining count instead of charging. Packs expire after 60 days, can be extended once by 30 days within the last 14, paused once, and unused sessions are forfeited at expiry. Packs live entirely in payment; booking only stores sessionPackPurchaseId.

    See Payment · Code PackSessionService, SessionPackPaymentService, SessionPackTier, SessionPackPurchase (payment.session_pack_purchases)

    Session plan

    What the coach intends to run in one booked session: up to four ordered blocks of drills plus a development focus, Session DNA and equipment list. It is one-to-one with a booking and can only be created while the booking is CONFIRMED. Status goes DRAFT → SAVED → COMPLETED (or CANCELLED). SLU is only computed for sessions with a saved or completed plan. Called "session" in the code (session.sessions), which is easy to confuse with the booking.

    See Session · Code SessionPlanService, Session (session.sessions), /coach/session-builder/:bookingId

    Session Prep Card

    A pre-session briefing for one upcoming booking: the last attended session and its recap, a suggested "what's next", focus-thread skills, open neglected skills, the player's own request and the coach's private plan note.

    See Development · Code SessionPrepService, SessionFocusThreadCalculator

    Shadow (player) profile

    A PlayerProfile a parent creates for their child. It is not a User and has no login. It is owned through parent_id and linked by ParentPlayerLink, and a minor's profile requires explicit parental consent at creation. Every minor on the platform is a shadow profile; the parent books, pays, approves videos and exercises GDPR rights on the child's behalf.

    See Security · Code ShadowAccountService.createPlayerProfile, ParentPlayerLink, table main.player_profiles (CHECK chk_pp_owner)

    ShedLock

    The library that makes a @Scheduled job run on only one instance at a time. Methods annotated with @SchedulerLock(name = …) take a row lock in main.shedlock, using DB time. 32 of the 41 scheduled methods use it; the rest are safe per instance by design (per-node caches, or SKIP LOCKED claims). Scheduling is off under the test profile.

    See Scheduled Jobs · Code infrastructure.config.ShedLockConfig, table main.shedlock

    Signed playback

    Video is never served by a public URL. After VideoAccessGuard authorises the viewer (owner, parent, admin, or a coach inside the access window), PlaybackService issues a short-lived signed streaming URL plus a playback token that can be revoked. COACH_REVIEW videos never get a download URL.

    See Video · Code PlaybackService, VideoAccessGuard, PlaybackToken (main.playback_tokens), app.video.playback.signing-secret

    Skills Radar

    A coach-judged 0–100 ability score per skill, the weighted composite of up to three assessment types: OBJECTIVE (50%), MATCH_OBSERVATION (30%) and COACH_EVALUATION (20%). The composite is recomputed asynchronously after each submission, and the first composite per skill is frozen as a baseline for measuring improvement. Requires an INSTRUCTOR or ACADEMY coach. Deliberately separate from SLU.

    See Development · Code RadarAssessmentService, RadarCompositeCalculationService, tables development.player_radar_composites, development.player_radar_baselines

    SKIP LOCKED claim

    The queue-draining pattern: SELECT … FOR UPDATE SKIP LOCKED so concurrent workers on different pods each take different rows instead of waiting. Used by the outbox, the webhook inboxes and several sweepers. It provides concurrency safety without ShedLock.

    See Scheduled Jobs, Outbox · Code OutboxMessageRepository.claimNextDue

    SLU (Skill Load Units)

    An objective training-volume metric computed per skill and drill when a session completes: rep density × skill weight × scaled intensity, pressure and match realism × duration. It is only computed for attended sessions with a saved or completed plan. Detail rows are append-only, and weekly snapshots feed the exposure dashboard and neglected-skill detection. It measures volume, not ability.

    See Development · Code SluFormula, SluCalculationService, tables development.player_skill_stats, development.player_slu_weekly_snapshot

    T

    Template

    A coach's reusable copy of a session plan's blocks, DNA, equipment and focus. It can be deployed onto a CONFIRMED booking picked from a list, which creates that booking's plan. Templates are ACTIVE or ARCHIVED and track a deploy count.

    See Session · Code SessionTemplateService, SessionTemplate (session.session_templates), /coach/session-templates

    Three-layer video moderation

    Every uploaded video passes, in order: (1) Arachnid, CSAM hash matching, where a match locks the video, alerts admins and suspends the account; (2) VideoIntel, Google Video Intelligence explicit-content detection, where a flag locks the video; (3) the minor-safety gate, a fail-closed re-check (minors are refused at upload initiation). Each layer's latest outcome is stored per video. A layer outage leaves the video in SCANNING for an SLA monitor to retry through the outbox. Layers 1 and 2 can be switched off via AppFeature.

    See Video · Code ModerationOrchestrationService, VideoModerationScan (main.video_moderation_scans), ModerationSlaMonitorService

    Timeline

    The player's chronological development feed: completed sessions (with drills, ratings and recap), homework assigned, radar assessments and shared reports. Written by event listeners in their own transactions, replay-safe (one SESSION_COMPLETED per player and booking), and scrubbed on coach erasure.

    See Development · Code TimelineEventListener, TimelineQueryService, PlayerTimelineEvent (development.player_timeline_events)

    Tombstone

    A sticky "this subject was GDPR-erased" marker that stops late writers from recreating scrubbed data. main.player_profiles.development_data_erased_at (V151) is checked under lock by development listeners. marketplace.coach_profiles.recap_data_erased_at (V166) is set inside the coach scrub and blocks recap edits. Writers must check the tombstone after taking their own row lock. A coach's account lock alone is not a reliable erasure signal.

    See Database, Admin · Code DevelopmentDataErasureGuard, BookingCompletionService (recap editability)

    V

    Verification status

    How far a user got through registration: UNVERIFIED → EMAIL_VERIFIED → BASIC_VERIFIED (phone OTP done), or SUSPENDED. Login requires BASIC_VERIFIED only when security.registration.phone-otp-required is true; it is seeded false, so email verification is enough. This describes the account, unlike the coach's verification tier.

    See Security · Code enum SkillarsVerificationStatus, AuthService.login

    Verification tier

    An admin-assigned trust badge on a coach's marketplace profile: BASIC (default), TRUSTED or FEATURED. It is shown on coach cards, the public profile and reports. The column is updatable = false on the entity and is written only by the admin's bulk update.

    See Admin, Marketplace · Code AdminCoachEnforcementService, CoachProfileRepository.updateVerificationTier, column marketplace.coach_profiles.verification_tier (CHECK chk_verification_tier)

    W

    Wrap-up

    The coach's end-of-session form: attendance, effort/focus/technique ratings, up to two homework drills, the recap, and the LIVE or QUICK mode. Submitting it completes the booking (or moves it to pending confirmation) and publishes BookingCompletedEvent. That event starts the payout hold, SLU, timeline, homework and plan completion. Abandoned wrap-ups are force-completed.

    See Booking · Code BookingCompletionService.submitWrapUp, WrapUpRequest, POST /api/bookings/{id}/complete, WrapUpSequence.vue
