Admin / Staff

Internal Skillars staff — operations, trust & safety, and platform partnerships. This page is scoped honestly: it covers what's actually clickable in the UI today, separately from what's real backend capability with no UI yet.

Who this persona is

Admin/staff accounts run the business behind the scenes: keeping the infrastructure healthy, managing external B2B integration partners, and — per the backend capability documented in the technical docs — moderating content, resolving disputes, enforcing coach reliability, and handling GDPR data requests. As of this build, only the first two have a real frontend; the rest are operated directly against the API (e.g. via internal tooling or direct API calls), not through a Skillars admin screen.

What's actually in the UI today

flowchart LR
    A["/admin/health-dashboard"] -->|"UP/DOWN + per-component detail"| B[Ops visibility]
    C["/admin/tenants"] --> D["/admin/tenants/:tenantRef"]
    D -->|"manage API keys, webhook config"| E[B2B partner integrations]

1. System health

  1. /admin/health-dashboard: an overall UP/DOWN status pill, plus a card per backend component (database, cache, external providers, etc.) with status and detail rows. Non-admin users see only the overall pill with an "Admin access required" notice instead of component details.

2. Managing B2B tenants

Why it matters: a "tenant" here is not a club or organization using Skillars — it's an external business partner integrating with Skillars over API, authenticated by API key. This is a common naming trap; see the callout below.

  1. /admin/tenants: a filterable, paginated table of tenants (filter by status: active/suspended/etc.) with a "Create Tenant" button.
  2. Clicking a row opens /admin/tenants/:tenantRef — the detail/management screen for that specific partner (API key issuance/rotation, webhook configuration).

What's real but API-only (no admin UI yet)

The backend fully supports the following — they're documented in depth in the technical docs — but there is currently no admin-facing screen for any of them:

Trust & safety moderation

A unified moderation queue fed by reports from messaging, reviews, and video — real backend endpoints, no UI.

Coach enforcement

Reliability strikes, visibility reduction, and suspension for repeated late cancellations/no-shows.

Dispute resolution

Handling disputes raised over a booking.

GDPR requests

Data export and erasure requests — legally time-boxed, currently operated without a dedicated screen.

Review moderation

AI + flag-based moderation of coach reviews before they go public.

Conventions & Gotchas

Don't promise a stakeholder a moderation/dispute/GDPR dashboard — none exists in the frontend today. If someone asks "where do I go to approve a GDPR erasure request," the honest answer is: nowhere in the UI yet — it's handled directly against the backend.

"Tenant" means external API partner, not club/organization. There's no per-club multi-tenancy in Skillars — every coach/player/parent shares the same platform regardless of which club or program they belong to.

Related Personas

Coach

Reliability enforcement and dispute resolution act on coach accounts, even though there's no admin screen for it yet.

Parent

GDPR requests and content moderation most often originate from a parent's concerns about their child's data or safety.
